## قواعد ثابتة (ليست ديونًا — للالتزام بها في أي كود جديد)

1. **الوقت**: استخدم `app/time_utils.py` دائمًا (`utcnow` / `ensure_utc` / `to_local` /
   `format_local`). التخزين UTC، والمرجع للعرض وحدود الفترات `Africa/Algiers`.
   ممنوع `datetime.utcnow()` ومقارنة وقت aware مع naive مباشرة. لا تُغيّر تنسيق التاريخ
   داخل `verification._canonical_payload` (يُبطل رموز QR المطبوعة).
2. **flake8**: `extend-ignore` يحتوي فقط `E501, W503, E203`، و`max-complexity = 10`؛
   أي كود جديد يجب أن يمرّ بلا مخالفات (دالة تتجاوز 10 تُقسَّم إلى دوال مساعدة).
   بعد أي نسخ/لصق شغّل `poetry run python scripts/fix_eof_newline.py`
   (يعالج `W292`/`W293`/`W391`). المقارنات المنطقية على أعمدة SQLAlchemy بـ
   `.is_(False)` / `.is_(True)`.
3. **الاختبارات**: `test_suite/` و`test_suite_invoices/` يجب أن تنجح كلها قبل أي دمج
   (CI يشغّلهما معًا)؛ أي تغيير في سلوك API يُرافقه تحديث اختباراته في نفس التعديل.
   اختبارات تحتاج فِكستشرات الفوترة (`customer`, `make_chassis`, ...) مكانها
   `test_suite_invoices/` وليس `test_suite/`.
4. **المبالغ في الـ API**: كل مسار يُرجع مبالغ يجب أن يملك `response_model` بحقول `Decimal`
   (تُسلسَل نصًا بمنزلتين عشريتين `"400.00"`)؛ لا تُرجع `dict` خامًا فيه `Decimal`
   (يتحول إلى `float`) ولا تستخدم `x or 0` على مبلغ (الصفر `Decimal("0.00")` قيمة خاطئة منطقيًا).

## قاعدة الإضافة المستقبلية

عند رصد أي ملاحظة جديدة (سواء أثناء تطوير، مراجعة كود، أو نتيجة CI):
1. أضف قسمًا جديدًا هنا بنفس القالب (الملف / الوصف / الخطر / لماذا مؤجل / متى نعالجه / التاريخ).
2. لا تنشئ ملف `.md` منفصل جديد مهما كانت الملاحظة صغيرة.
3. صنّف الأولوية بوضوح: `[عاجل]` / `[متوسط]` / `[منخفض]` / `[معلومة/بلا إجراء مطلوب]`.
4. عند إنجازها بالكامل احذف قسمها (وأي إحالة إليه من الكود).
